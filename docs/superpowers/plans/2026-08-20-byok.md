# BYOK (Bring Your Own Key) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let users configure native foreign-model agents with zero harnesses installed — pick a provider from the well-known list, fetch its model catalogue from the `/models` endpoint, enter an API key, and go.

**Architecture:** The well-known provider URLs (35+ entries in `src/detect.ts`) are already there. BYOK adds: (1) a model-fetcher that probes any OpenAI-compatible `/models` endpoint and returns a list, (2) a BYOK flow in the Ink wizard that shows well-known providers as selectable items alongside harness-discovered ones, (3) inline key entry when a selected provider has no key.

**Tech Stack:** TypeScript, Node built-in `fetch`, Ink React components (existing), vitest.

**Spec:** Approved design from conversation (2026-08-20): well-known provider picker + fetched model lists from `/models` endpoints + manual model ID fallback + inline key prompt. Works with zero harnesses.

## Global Constraints

- Tests need no API keys and no network — the model fetcher is injected in tests.
- Keys never logged, never in conversation, never in argv — sonata's own store only.
- `sonata` on PATH runs `dist/` — `npm run build` before any live test.
- Run `npm test` and `npm run typecheck` before considering a task done.
- Also update `README.md` with BYOK documentation.

### Task 1: Model fetcher — probe `/models` endpoints

**Files:**
- Create: `src/native/models.ts`
- Test: `tests/native/models.test.ts`

**Interfaces:**
- Consumes: `WELL_KNOWN_PROVIDER_URLS` from `../detect.js` (exported in this task).
- Produces:
  ```ts
  export interface FetchedModel { id: string; name?: string }
  /** Probes an OpenAI-compatible /models endpoint and returns the model list.
   *  Returns [] on timeout/error — never throws. */
  export async function fetchModels(
    baseUrl: string,
    apiKey: string,
    opts?: { fetch?: typeof fetch; timeoutMs?: number },
  ): Promise<FetchedModel[]>

  /** The well-known provider list, exported for the wizard. */
  export function wellKnownProviders(): Array<{ name: string; url: string }>
  ```

- [ ] **Step 1: Write failing tests**

```ts
import { fetchModels, wellKnownProviders } from '../../src/native/models.js';

it('parses an OpenAI /models response', async () => {
  const fake = async () => new Response(JSON.stringify({
    data: [{ id: 'gpt-5.6-luna', object: 'model' }, { id: 'gpt-5.6-terra' }],
  }));
  const models = await fetchModels('https://api.example.com/v1', 'sk-test', { fetch: fake });
  expect(models).toEqual([{ id: 'gpt-5.6-luna' }, { id: 'gpt-5.6-terra' }]);
});

it('returns [] on network error', async () => {
  const fake = async () => { throw new Error('offline'); };
  expect(await fetchModels('https://api.example.com/v1', 'sk-test', { fetch: fake })).toEqual([]);
});

it('returns [] on non-JSON response', async () => {
  const fake = async () => new Response('<html>not found</html>', { status: 404 });
  expect(await fetchModels('https://api.example.com/v1', 'sk-test', { fetch: fake })).toEqual([]);
});

it('wellKnownProviders returns a non-empty list with urls', () => {
  const providers = wellKnownProviders();
  expect(providers.length).toBeGreaterThan(30);
  expect(providers.every(p => p.name && p.url)).toBe(true);
  expect(providers.find(p => p.name === 'openai')?.url).toBe('https://api.openai.com/v1');
});
```

- [ ] **Step 2: Run → FAIL** (`npx vitest run tests/native/models.test.ts`)

- [ ] **Step 3: Implement**

`fetchModels`: `fetch(baseUrl + '/models', { headers: { Authorization: 'Bearer ' + apiKey }, signal: AbortSignal.timeout(opts?.timeoutMs ?? 10000) })`, parse JSON, extract `data[].id` and optional `name`. Wrap in try/catch, return `[]` on any error.

`wellKnownProviders`: import `WELL_KNOWN_PROVIDER_URLS` (needs to be exported from `detect.ts`) and return `Object.entries(map).map(([name, url]) => ({ name, url }))`, deduped by URL (several aliases point to the same endpoint).

Export `WELL_KNOWN_PROVIDER_URLS` from `src/detect.ts` (add `export` keyword).

### Task 2: BYOK providers in the Ink wizard

**Files:**
- Modify: `src/tui-ink/app.tsx`
- Modify: `src/tui-ink/app-state.ts`
- Modify: `src/tui-ink/types.ts`
- Modify: `src/commands/init.ts`
- Test: `tests/tui-ink/app-state.test.ts`

**Interfaces:**
- Consumes: `wellKnownProviders()` (Task 1), `fetchModels()` (Task 1), `resolveKeys`/`writeSonataKey` from `native/credentials.js`.
- Produces: updated `WizardData` with a `byokProviders` field; updated `InitState` with `byokKeys` for inline-entered keys.

**What changes:**

1. `WizardData` gains:
   ```ts
   byokProviders: Array<{ name: string; url: string }>;
   ```

2. `InitState` gains:
   ```ts
   byokKeys?: Record<string, string>;  // provider -> key entered inline
   ```

3. The wizard's **step 1 (Harnesses)** becomes optional — if no harnesses are installed, skip straight to a provider picker.

4. The wizard's **step 2 (Providers)** is extended: after showing harness-discovered providers, it shows a "--- BYOK Providers ---" section with well-known providers not already covered by harness discovery. The user can select from both.

5. The wizard's **step 3 (Models)** is extended: for BYOK providers (those without harness-discovered models), the wizard:
   a. Checks if a key exists (from sonata store or opencode auth).
   b. If no key, shows an inline text prompt ("API key for <provider>:") — non-echoing, stored via `writeSonataKey`.
   c. Calls `fetchModels(url, key)` to get the model list.
   d. If fetch succeeds, shows the models as a MultiSelect.
   e. If fetch fails or returns empty, shows a text prompt ("Enter model IDs for <provider>, comma-separated:").

6. `cmdInit` passes `byokProviders: wellKnownProviders()` into `WizardData`.

7. After the wizard returns, `cmdInit` writes any `byokKeys` from `state` to the sonata key store.

- [ ] **Step 1: Update types** — add `byokProviders` to `WizardData`, `byokKeys` to `InitState`.

- [ ] **Step 2: Update `cmdInit`** — pass `byokProviders: wellKnownProviders()` and write `state.byokKeys` after the wizard returns.

- [ ] **Step 3: Update the wizard steps:**
  - Step 1 (Harnesses): if `data.harnesses.filter(h => h.installed).length === 0`, auto-advance (set `harnesses: []`, go to step 2).
  - Step 2 (Providers): merge harness-discovered providers with BYOK providers. BYOK providers are items from `data.byokProviders` whose `name` is not already a gateway in any harness-discovered provider. Each shows as `{ value: 'byok/' + name, label: name, hint: 'BYOK · ' + url }`.
  - Step 3 (Models): split into two sub-flows per selected provider:
    - If it's a harness-discovered provider: show candidates as before.
    - If it's a `byok/` provider: key check → fetch models → MultiSelect or text prompt.

- [ ] **Step 4: Update app-state tests** — test that BYOK provider keys and manually-entered model IDs flow through `applyStep` correctly.

### Task 3: BYOK candidates to native config

**Files:**
- Modify: `src/commands/init.ts`
- Test: `tests/init.test.ts`

**Interfaces:**
- Consumes: `TuiResult.state` with BYOK-entered models and keys.

**What changes:**

When `cmdInit` processes the wizard result, BYOK-selected models need to become `NativeCandidate[]` so the existing `nativeTomlFor` can write them. The mapping:

- For each BYOK provider key in `state.providerKeys` starting with `byok/`:
  - `gateway` = the provider name (after `byok/`)
  - `baseUrl` = from `wellKnownProviders()` lookup
  - For each model selected for that provider:
    - `key` = `gateway-modelId` (flattened)
    - `id` = the model ID
    - `contextWindow` = 128000 (default)
  - These candidates merge with the harness-discovered ones.

The non-interactive (flag) path gains `--provider <name>` and `--key <key>` for BYOK without a wizard:

```bash
sonata init --yes --provider openai --key sk-... --models gpt-5.6-luna --roles code
```
